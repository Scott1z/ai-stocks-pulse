<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser push service → service worker `push` event | `event.data` is attacker-influenceable in principle: any party holding this device's subscription (endpoint + `p256dh` + `auth`) can deliver an arbitrary encrypted payload that this handler renders |
| notification `data.url` → `clients.openWindow` | A URL carried in the push payload decides where the click navigates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | `push` listener | mitigate | Payload is read as `event.data ? event.data.json() : {}` with `||` defaults on every field, so a missing or partial payload renders the "AI QuickCap" fallback notification instead of throwing and leaving `userVisibleOnly` unsatisfied |
| T-03-02 | Tampering (open redirect) | `notificationclick` target URL | mitigate | The click target is resolved with `new URL(value, self.registration.scope)` and the focus branch only matches clients whose `url` starts with `self.registration.scope`; the app is single-page so the only intended destination is the homepage. Phase 3's `api/send-push.js` is the sole sender and is secret-gated (TRIG-02) |
| T-03-03 | Information Disclosure | notification body text | accept | The body is the same public sector narrative already rendered on the homepage — no private or per-user data is ever placed in a push payload (REQUIREMENTS.md rules out personalised digests entirely) |
| T-03-04 | Spoofing | rendered notification content | accept | Web Push payloads are encrypted per RFC 8291 to this device's `p256dh`/`auth`; only a holder of the stored subscription record can produce a decryptable payload. The residual risk is fully inherited from subscription-record confidentiality, mitigated in plan 01-02 (T-02-02) |
| T-03-05 | Tampering | stale worker after update | mitigate | `CACHE_NAME` bump to `ai-stocks-pulse-v46` triggers the existing `activate` cache-eviction path plus `self.clients.claim()`, so installed PWA users converge on the worker that actually has the push handlers rather than silently dropping pushes |
| T-03-SC | Tampering | package installs | mitigate | This plan installs nothing — pure edits to one existing vanilla JS file, no `package.json`, no npm, no CDN script. Supply-chain surface is empty by construction |
</threat_model>
