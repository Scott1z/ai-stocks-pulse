<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local shell → git-tracked repo | The VAPID private key is generated in the shell; anything that crosses into a tracked file is published to a public GitHub repo permanently |
| local shell → Vercel env store | Authenticated CLI write of a long-lived secret; value travels over the CLI session |
| server (Vercel Function, later phases) → browser push service | The private key is the sole proof of sender identity for every future push; its public half is shipped to every visitor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `.env.local` / git | mitigate | Write the private key only to `.env.local`, which `.gitignore:22` (`.env*`) already covers; Task 2 verify asserts `git check-ignore -q .env.local` and that `git grep -F` finds the private key value in zero tracked files |
| T-01-02 | Information Disclosure | terminal transcript / SUMMARY / `.planning/` | mitigate | Capture keygen stdout into a shell variable, never `cat`/`echo` the private key, forbid recording it in commit messages or the SUMMARY; only the public key may be recorded |
| T-01-03 | Spoofing | client `app.js` ↔ server VAPID env vars | mitigate | Both halves come from a single `generate-vapid-keys` run; Task 3 verify asserts the `app.js` literal is byte-identical to `.env.local`'s `VAPID_PUBLIC_KEY`, preventing the 401/403-on-every-send failure mode of PITFALLS Pitfall 1 |
| T-01-04 | Repudiation / Denial of Service | VAPID key pair lifecycle | mitigate | Explicit "generate once, never rotate" instruction in Task 2; rotation silently kills every subscription with no rollback (STACK.md) |
| T-01-05 | Elevation of Privilege | Vercel env store scope | accept | The key is added to Preview and Development as well as Production so `vercel dev` and preview deploys work; Preview deployments of a public repo are a lower-value target than the key's absence would cost in broken local testing |
| T-01-SC | Tampering | `npx web-push`, `npx vercel` (supply chain) | mitigate | No `## Package Legitimacy Audit` exists in `.planning/research/`, so both packages are treated as [ASSUMED]; Task 1 is a blocking-human legitimacy checkpoint on npmjs.com (publisher, repo link, download volume, typosquat check) that must pass before any `npx` invocation. Not auto-approvable regardless of `workflow.auto_advance` |
</threat_model>
