<!-- and documented in scripts/push_redis.py's module docstring (lines 11-33). -->

Redis hash key:  push:subscriptions
Hash field:      sha256(subscription.endpoint) hex digest (lowercase hex, 64 chars)
Hash value:      compact JSON of exactly PushSubscription.toJSON():
                 { "endpoint": string,
                   "expirationTime": null | number,
                   "keys": { "p256dh": string, "auth": string } }
Upsert:          HSET push:subscriptions <field> <json>
Point read:      HGET push:subscriptions <field>
Delete:          HDEL push:subscriptions <field>   (returns 0 if absent — not an error)
Enumerate:       HGETALL push:subscriptions        (single command, never KEYS/SCAN)

Environment variables (already provisioned in Vercel and in local .env.local by Phase 1):
  KV_REST_API_URL
  KV_REST_API_TOKEN
Redis.fromEnv() reads UPSTASH_REDIS_REST_URL/TOKEN *or* KV_REST_API_URL/TOKEN —
this project only has the KV_* pair, and the fallback is confirmed working
(source: upstash-redis-js.mintlify.app/platforms/vercel, verified in 02-RESEARCH.md Pattern 3).

Existing Python validation contract to port (scripts/push_redis.py put(), lines 149-169):
  endpoint       must be a non-empty string
  keys.p256dh    must be a non-empty string
  keys.auth      must be a non-empty string
  otherwise -> reject, never write

Existing Python delete contract to port (scripts/push_redis.py delete(), lines 200-209):
  HDEL result of 0 is a normal outcome, not an error.

Existing verification CLI (Phase 1, no new tooling needed):
  python3 scripts/push_redis.py get <endpoint>   -> prints the stored JSON or nothing
  python3 scripts/push_redis.py list             -> lists all stored subscriptions
  python3 scripts/push_redis.py del <endpoint>   -> prints HDEL count
