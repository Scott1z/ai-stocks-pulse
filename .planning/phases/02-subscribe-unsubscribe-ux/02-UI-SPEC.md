# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — vanilla CSS, hand-authored design tokens (no build step, per CLAUDE.md constraint) |
| Preset | not applicable |
| Component library | none — hand-rolled markup/CSS, documented component recipes in `DESIGN.md` |
| Icon library | none — hand-rolled inline SVG (stroke `currentColor`, 1.6–1.7 stroke-width, round caps/joins), same recipe as `.theme-toggle`, `.topbar-nav`, Trend Glyphs, Category Icons |
| Font | Montserrat only (self-hosted, `fonts/Montserrat-*.woff2`) — One-Font Rule, no exceptions (see MEMORY: "Single font, no exceptions") |

This phase introduces **zero** new design primitives. Every new element (soft-ask banner, topbar toggle, iOS message) is required by `02-CONTEXT.md` to reuse an existing component family (`showToast()`/`.toast`, `.theme-toggle`/`.btn-ghost`, `initInstallPrompt()`). No shadcn init gate applies — this project has no React/Next/Vite tooling and no `components.json`; it is intentionally zero-dependency per `CLAUDE.md`.

## Spacing Scale

This codebase does not run a literal 4/8-point token system — it has hand-tuned, already-in-production values that this phase must match exactly rather than impose a new abstract scale onto:

| Token | Value | Usage (existing precedent) |
|-------|-------|------|
| xs | 4px | Icon-to-label gap inside pill/badge components |
| sm | 8px | `.topbar-actions` gap between topbar controls (`gap: 12px` is the actual measured value — see exception below) |
| md | 16px | `.btn` horizontal padding (`9px 16px`), banner internal padding |
| lg | 24px | Toast/banner offset from viewport edge (`bottom: 24px`) |
| xl | 32px | Modal panel padding (unused by this phase, listed for reference only) |

Exceptions (already established in the codebase, reuse verbatim — do not "correct" to a clean 4/8 value):
- `.btn` padding is `9px 16px` (existing, `styles.css:478`) — new soft-ask "Activar" button and topbar toggle must match this exactly, not round to `8px 16px`.
- `.toast` padding is `12px 20px` (existing, `styles.css:2142`) — reuse for the soft-ask banner's internal padding.
- `.topbar-actions` gap is `12px` (existing, `styles.css:382`) — the new topbar toggle slots into this row and inherits the 12px gap automatically; do not add a manual margin.
- `.theme-toggle` is a fixed `30px × 30px` circular hit target (existing, `styles.css:388-389`) — the new push-toggle button must be pixel-identical (30×30, pill radius, 15×15 icon) since D-03 requires it to sit "next to the existing theme toggle button... same ghost-button visual language."

## Color

No new hex values. Every element in this phase draws from tokens already defined in `:root` (light) and `:root[data-theme="dark"]` (dark) blocks in `styles.css`.

| Role | Value (token) | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper` | Page background behind the banner (banner itself floats above it) |
| Secondary (30%) | `--panel` | Soft-ask banner background, matches `.toast`'s panel-adjacent surfaces |
| Accent (10%) | `--accent` (Ledger Navy light / sky-blue dark) | Reserved for: (1) the "Activar" button's hover/focus border+text per `.btn-ghost:hover`, (2) the topbar bell icon's **subscribed** state fill (solid accent, same recipe as the Watchlist Star's "fills solid accent once starred"), (3) `:focus-visible` outline on both new interactive elements |
| Destructive/muted (denied state) | `--text-faint` | The bell icon and its help text in the **denied** state — deliberately *not* a red/destructive color, since permission-denial isn't an error the user caused in-app; matches the Market Status Pill's "closed" treatment (`--text-faint`, no color emphasis) |

Accent reserved for: the "Activar" CTA's hover/focus state, the topbar toggle's subscribed-state icon fill, and focus rings on both — nothing else in this phase gets accent color. The denied state and the iOS install-first message stay in `--text-dim`/`--text-faint` (quiet, per FEATURES.md's "never over-engineer the denied state" guidance) — never accent, never a semantic red (this is not an error).

Exact copy in Spanish, matching the site's existing terse, informative tone (cf. "Instalar app", "¡App instalada!", "Mercado cerrado"). These are Claude's-discretion items per `02-CONTEXT.md` — locked here as defaults, not re-asked of the user since CONTEXT.md explicitly delegated them.

| Element | Copy |
|---------|------|
| Soft-ask banner body | "Recibí el resumen del sector todos los días al cierre del mercado, sin abrir la app." |
| Primary CTA (soft-ask banner button) | **"Activar"** — exact label locked by D-02, do not append "notificaciones" to the visible button (keep it short for the banner's compact layout); the button's `aria-label` may be the fuller "Activar notificaciones" for screen readers |
| Soft-ask dismiss control | Close (×) icon-only button, `aria-label="Cerrar"` — no text label, matches modal close-button pattern |
| Topbar toggle — unsubscribed state | `aria-label="Activar notificaciones"`, outline bell icon (unfilled, `--text-dim`) |
| Topbar toggle — subscribed state | `aria-label="Notificaciones activadas — click para desactivar"`, filled bell icon (`--accent`) |
| Topbar toggle — denied state | `aria-label="Notificaciones bloqueadas por el navegador"`, outline bell-with-slash icon (`--text-faint`), **not a button** in the sense of triggering any JS prompt — click reveals the denied help message inline/as a toast rather than doing nothing silently |
| Denied-permission help message (quiet, shown via `showToast()` or an inline note on toggle click) | "Bloqueaste las notificaciones en tu navegador. Para activarlas, entrá a la configuración del sitio (ícono de candado en la barra de direcciones) y permitilas." |
| iOS "install first" message (replaces a functional enable control for iOS Safari tabs not in standalone mode) | "Las notificaciones en iPhone requieren instalar la app primero. Tocá compartir → \"Agregar a inicio\", abrí AI QuickCap desde el ícono nuevo y activalas desde ahí." — styled as a quiet inline note using the existing `.btn-ghost`-adjacent muted-text pattern, not a functional button (since there's no JS API to trigger `beforeinstallprompt` on iOS) |
| Subscribe success confirmation | Toast (reuse `showToast()`): "¡Notificaciones activadas!" — same recipe/timing as "¡App instalada!" |
| Unsubscribe confirmation | Toast: "Notificaciones desactivadas." |
| Subscribe failure (e.g., service worker registration or `pushManager.subscribe()` rejects) | Toast: "No se pudo activar las notificaciones. Probá de nuevo más tarde." — matches the project's silent-degradation error philosophy (no `alert()`, no thrown-exception UI, always a soft fallback) |
| Destructive action | **Unsubscribe** is the only removal-type action in this phase. Confirmation approach: **none** — a single tap/click on the topbar toggle unsubscribes immediately (per OPTIN-05's explicit "one action" requirement and FEATURES.md's "one-tap unsubscribe, symmetric with subscribe" table-stakes guidance). No modal, no "are you sure?" dialog — this is reversible (re-subscribing is equally one tap) and low-stakes, unlike e.g. deleting account data. A toast confirms the action happened, which is sufficient feedback. |

## Component Inventory (new for this phase)

Beyond the standard template sections above, the following concrete build notes apply — for the planner/executor, since this project has no component library to point to instead:

### 1. Soft-Ask Banner
- **Markup shape:** a new fixed-position element (suggest `#pushSoftAsk`, not reusing `#toast`'s id/element since it needs a persistent button + close control, not just auto-dismissing text), inserted once in `index.html` near the existing `<div id="toast">`.
- **Position:** `position: fixed; bottom: 24px` (matches `.toast`'s existing offset), horizontally centered on desktop, full-width with side insets on mobile (`< 640px`) — same responsive posture as the toast.
- **Surface:** `--panel` background, 1px `--line` hairline border (not the toast's inverted `--text`-on-`--paper` treatment — the banner needs to hold a visible secondary button, so it needs the same neutral surface as a modal/card, not an inverted pill), `4px` radius (Two-Radius Rule: structural container, not a status pill), Toast Float shadow (`0 10px 30px -12px rgba(16,24,40,.35)`).
- **Layout:** flex row — explanatory text (body voice, `--text`) — "Activar" button (`.btn.btn-ghost`, exact existing recipe) — close (×) icon button (matches modal close-button sizing/style) — wraps to a stacked layout under ~480px if the row doesn't fit.
- **Trigger:** appears once, after a dwell time on the page (Claude's discretion per CONTEXT.md — default **6 seconds**, landing between the research-suggested ~5s anchor and giving one extra beat past the hero content's typical render time), gated by: `Notification.permission === "default"` AND not already dismissed/subscribed this session (`localStorage` flag, e.g. `aisp_push_soft_ask_seen`). Never re-triggers automatically after dismissal via × — matches FEATURES.md's explicit anti-nagging guidance and CONTEXT.md's discretion note; the only path back is the persistent topbar toggle.
- **Motion:** reuse the existing toast's opacity/translateY entrance transition (`0.2s ease`), respects `prefers-reduced-motion` via the sitewide blanket rule — no bespoke animation needed.

### 2. Topbar Push Toggle
- **Markup:** a new `<button id="pushToggle" class="theme-toggle">` (literally reusing the `.theme-toggle` class per D-03 — "same ghost-button visual language, not a new component family"), placed in `.topbar-actions` between `#themeToggle` and `#installBtn`.
- **Dimensions:** `30×30px`, pill radius, `15×15px` icon — pixel-identical to `.theme-toggle` (see Spacing exceptions above).
- **Three-state icon swap:** same dual-icon-swap CSS pattern as `.theme-toggle`'s sun/moon (`display: none/block` toggled by a state attribute, e.g. `data-push-state="default|subscribed|denied"` on the button itself, mirrored in `:root[data-theme]`'s pattern) — do not invent a new state-toggling mechanism, reuse the exact one already proven for the theme icon.
- **Icons:** hand-rolled inline SVG bell (outline for unsubscribed/denied, filled for subscribed) at the same stroke-width (1.7) and style as the rest of the topbar's icon set — no icon library.

### 3. iOS Install-First Message
- **Where it appears:** in place of a functional toggle for visitors on iOS Safari (detected via `navigator.standalone === false` or `!window.matchMedia('(display-mode: standalone)').matches` combined with an iOS UA/platform check) who haven't added the app to their home screen. Per CONTEXT.md, reuses the *pattern* of `initInstallPrompt()`/"Instalar app," not its literal `beforeinstallprompt` logic (which iOS never fires).
- **Style:** quiet inline text near the topbar toggle position or inside the soft-ask banner body (planner's call at implementation time) — never a button that looks actionable but does nothing on tap, per FEATURES.md Pitfall: "never show a generic enable button that silently fails on iOS."
